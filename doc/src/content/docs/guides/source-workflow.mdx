This side project selects information for documentation, not components for a new fabricated board. All imported inventory lines are marked not fitted and have no declared placements. The original instrument inventory is preserved separately for provenance.

Each profile distinguishes source identity, acquisition, inherited verdicts, current research commentary, model fidelity and assembly status. A part rejected from one compact layout may be excellent in a different instrument. A known name or catalogue code is not a universal approval.

### Evidence layers

The authored profiles explain why a part matters and what to investigate. The native generated pages project the inherited exact-component bundles. Original source documents and CAD live outside public assets, with hashes and acquisition context. Historical candidates stay in research instead of being silently promoted to exact manufacturing selections.

An inherited `PASS` means the originating evidence record made a scoped claim at its recorded locator. It is not a new bench result, a present stock guarantee or this corpus's blanket endorsement. `SOURCE UNAVAILABLE` and identity gaps remain visible.

### Updating the corpus

Start from the complete manufacturer/MPN/package identity. Acquire and inspect the actual source bytes, record the URL/date/hash and exact locator, then update only the claims it supports. A family model can be reused as family geometry; it cannot acquire exact-vendor fidelity by renaming the file.

Use the canonical `circuit/WORKFLOW.md` for component promotion and generated output. Edit research profiles or source evidence, then regenerate; do not hand-edit `doc/src/content/docs/components/`.

### Public versus local assets

The source pack is retained for local research. The build deliberately links original document URLs. Review third-party terms before publishing raw vendor files or derived previews publicly. No site has been deployed and no hardware order is authorized by this corpus.
